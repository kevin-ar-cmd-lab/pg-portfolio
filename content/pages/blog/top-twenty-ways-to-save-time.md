The most useful time-saving practices were straightforward:

- Define acceptance criteria before implementation.
- Keep issues small and linked to one outcome.
- Write commit messages around intent, not file lists.
- Validate keyboard navigation while building.
- Reuse section components instead of creating one-off markup.
- Keep project content specific and measurable.
- Check metadata while content is being written.
- Document tradeoffs in short bullets during development.
- Use review checklists for each merge.
- Run a build check before final edits.

These habits reduced context switching and prevented most last-minute quality regressions.
