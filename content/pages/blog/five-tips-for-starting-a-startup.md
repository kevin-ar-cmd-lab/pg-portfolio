## 1. Scope must be explicit before coding starts

When feature boundaries were unclear, implementation drift happened quickly. Every project improved once scope, constraints, and success criteria were written before the first commit.

## 2. Content quality matters as much as component quality

A polished layout could still feel weak if copy was generic. Replacing placeholder text with specific project context increased reviewer confidence immediately.

## 3. Accessibility checks belong in daily workflow

Waiting until the end to test keyboard navigation and heading order created expensive rework. Small checks during each feature branch prevented larger regressions later.

## 4. Performance wins are usually basic

The biggest gains came from reducing unnecessary media payloads and defaulting to lazy loading, not from advanced optimization tricks.

## 5. Case studies close the credibility gap

Recruiters and mentors responded better when each project documented problem, constraints, decisions, and outcomes. A clear narrative made technical choices easier to evaluate.
